The problem

A single class can submit 60 assignments. Reading all of them and remembering who wrote what is impossible, so copied work slips through.

1

Manual checking does not scale

60 submissions means 1,770 possible pairs. No teacher can compare that many documents by hand before the deadline.

2

Online tools are paid and private

Most plagiarism services need a subscription and require uploading student work to a third-party server.

3

Small edits defeat exact search

Changing a few words breaks a simple "find this sentence" search, but the overall structure still stays almost identical.

Our solution

A scorer we wrote ourselves, running fully offline.

Every submission is cut into overlapping word groups called n-grams (shingles). Two assignments are then compared by asking a simple question: how many n-grams do they share out of all the n-grams they have together? That ratio is the Jaccard similarity.

The whole calculation is plain JavaScript. No library, no API, no upload — the data never leaves the browser.

View the Phase 1 pipeline

Jaccard similarity in one line

J(A, B) = |A ∩ B| / |A ∪ B|

  • A, B — the set of n-grams of each submission
  • ∩ — n-grams that appear in both
  • ∪ — all unique n-grams from both
Result is always between 0 (nothing common) and 1 (identical).

What Phase 1 includes

Everything below is built with HTML, CSS and vanilla JavaScript only.

✎

Submission form

Textarea with a live word counter and minimum / maximum word validation.

▤

N-gram tokenizer

Text is cleaned, lower-cased and split into overlapping word shingles.

∑

Pairwise scoring

Every submission is compared with every other one and given a score.

▦

Heatmap matrix

Colour coded grid rendered with the DOM, from safe green to high-risk red.

☰

Ranked suspicious list

Pairs sorted highest first so the instructor reviews the worst cases first.

↻

Browser storage

Submissions stay in LocalStorage, so the data survives a page refresh.
